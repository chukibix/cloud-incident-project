cloud-incident-platform

A self-hosted backend and monitoring stack, built to fail on purpose. Every layer — networking, compute, database, deployment — is provisioned from code and can be torn down and rebuilt from nothing. This page talks directly to the live API to generate load, so you can watch the system respond in real time.

about

The backend exposes a handful of endpoints that intentionally stress specific parts of the stack — CPU, database I/O, response latency, error handling — instead of hiding failure behind mocked demos. The goal is to observe real behavior: request queues building up, RDS metrics climbing in Grafana, pods slowing down under load.

Infrastructure is provisioned with Terraform, application deployments are handled by ArgoCD watching this repository, and CI builds, scans, and ships new images automatically on every push.

TerraformAWS EC2AWS RDS · Postgres k3sArgoCDTraefik PrometheusGrafanaNestJSGitHub Actions
1 Push to main — a commit lands on backend/
2 CI builds and scans — image is built, scanned with Trivy, pushed to ECR
3 Manifest updated — the new image tag is committed back to the repo
4 ArgoCD syncs — the cluster is rolled to match, with no manual step
